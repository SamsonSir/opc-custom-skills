# 巨量千川投放 SOP

当用户要求“跑巨量投放流程”“继续千川投放”“按桌面投放流程执行”时，优先使用本 skill，不要只给文字建议。

## 通用化目标

本 skill 必须在任意支持本地 shell、Node.js、Chrome CDP 与 skill 文件读取的智能体里跑通主链路。不要依赖当前智能体已经知道千川入口、ROI 口径、素材目录、上传脚本或历史页面坑位。

主链路定义为：

`环境探测 -> 构建投流输入 -> 进入商品全域投放创建页 -> 单商品单计划配置 -> ROI/预算/素材/标题填写 -> 默认发布 -> 输出执行结果`

如果外部依赖缺失，先明确指出缺失项与恢复动作；不要把缺依赖误判为投放失败。

## 通用运行契约

### 入口自定位

执行脚本时优先从 skill 自身目录启动：

```bash
cd ~/.agents/skills/qianchuan-launch-sop
node ./scripts/create_qianchuan_plan.js \
  --product-id <商品ID> \
  --sale-price <售价> \
  --unit-cost <成本价> \
  --sign-rate <签收率> \
  --product-name "<商品名>" \
  --material-dir "<clip_outputs里的商品素材目录>"
```

批量投流入口：

```bash
cd ~/.agents/skills/qianchuan-launch-sop
node ./scripts/batch_create_qianchuan_plans.js --input ./references/batch-launch.example.json --dry-run
```

不要要求用户进入某个 vault 项目目录才能执行。素材目录、参数文件和输出路径都应通过命令参数传入。

### 可配置项

| 变量 | 默认值 | 用途 |
|------|--------|------|
| `QIANCHUAN_CDP_PORT` | `9222` | 千川浏览器 CDP 端口 |
| `CDP_PORT` | `9222` | 兼容型 CDP 端口变量，低优先级 |

默认仍复用 9222，因为这是当前桌面主链路；外部智能体如果接入不同端口，优先设置 `QIANCHUAN_CDP_PORT`，不要改脚本源码。

### 运行前探测清单

1. `command -v node` 可用，且 Node 版本支持全局 `fetch` 与 `WebSocket`。
2. `curl http://127.0.0.1:${QIANCHUAN_CDP_PORT:-9222}/json/list` 能返回 tab 列表。
3. 目标浏览器已登录 `qianchuan.jinritemai.com`，并能访问目标账户。
4. 至少能从现有千川 URL 提取 `aavid`，或已有 tab 在 `/uni-creation/product` 创建页。
5. 输入参数中必须有 `product_id`、`sale_price`、`unit_cost`、`sign_rate`、`material_dir`。
6. `material_dir` 里必须有 `.mp4`，且这些素材应已由选品/剪辑链路处理为千川合规 9:16。

缺任一项时，停止主链路并给出具体恢复动作；不要在首页无限点击找入口。

### 输入契约

单商品最小输入：

```json
{
  "product_id": "1234567890123456789",
  "sale_price": 299,
  "unit_cost": 40,
  "sign_rate": 0.55,
  "material_dir": "/path/to/clip_outputs/商品目录"
}
```

推荐补充：

```json
{
  "product_name": "商品名",
  "title": "5-55字投流标题",
  "daily_budget": 300
}
```

批量输入顶层必须是数组。批量模式固定为“逐商品串行，每个商品新建一个单商品计划”。

### 输出契约

脚本执行完成后必须输出 JSON 或可解析摘要，至少包含：

- 当前商品是否成功
- ROI 计算结果与页面填写值
- 上传/复用的视频数量
- 标题填充结果
- 发布结果；若 `--no-publish`，明确说明停在发布前
- 失败时的阶段与可恢复动作

### 降级策略

- 找不到创建页：如果能从首页提取 `aavid`，脚本直达 `/uni-creation/product?aavid=<aavid>`；否则让用户在目标 CDP 浏览器中手动打开商品全域投放创建页。
- ROI 参数不足：补问 `sale_price`、`unit_cost`、`sign_rate`，不要沿用页面默认 ROI。
- 素材目录缺失或无 `.mp4`：停止投流，回到选品/剪辑链路生成素材。
- 上传到素材库但未挂载计划：继续勾选同名素材并确认到主页面，不重复上传。
- 平台拒绝素材尺寸：不要在投流脚本里临时转码，回到选品/剪辑阶段重出 9:16。

## 适用范围

- 巨量千川商品全域投放
- 复用用户已有 Chrome 登录态
- 需要上传 1 条或多条本地视频素材
- 商品 ID 可能失效，但用户仍希望先走完整流程

## 固定前提

1. 默认复用 `9222` 端口；如外部智能体使用其他 CDP 端口，设置 `QIANCHUAN_CDP_PORT`。
2. 浏览器必须是用户可复用登录态的那套 Chrome 会话。
3. 视频只走“本地上传”，不要改用“抖音号主页素材”等其他来源。
4. 默认自动点击 `发布计划` 并处理发布确认弹窗；只有用户明确要求“只配置不发布”或脚本传入 `--no-publish` 时，才停在发布前。

## 批量投流人审边界

批量投流的执行模型固定为：

- `1 个创建页 = 1 个商品 = 1 条投放计划`
- 批量是“逐商品串行新建单商品计划”，不是在同一个创建页里塞多个商品
- 如果当前页残留旧商品、多商品或错商品，脚本应先重置回干净创建页，再只添加当前商品
- 默认执行时，每个商品都脚本化点击 `发布计划`，发布成功后继续下一个商品；如果用户明确要求“只配置到发布前/不要发布”，必须用 `--no-publish` 脚本化停住，不要靠智能体手动控制。

批量商品投流时，人工只需要确认 4 个业务参数：

- 商品 ID
- 商品售价
- 成本价
- 签收率

其他项目默认脚本化，不要作为人工确认项反复询问：

- 商品名：来自选品/商品记录或千川页面商品卡
- 素材目录：来自选品/剪辑流程输出，例如 `clip_outputs/<商品序号>_<商品名>/`
- 标题：由脚本基于商品名生成，必须控制在 5-55 字，且不能留下空标题行或重复标题行
- 日预算：固定 300
- 发货率：固定 90%
- 利润率：固定 1%
- ROI：由脚本计算
- 视频尺寸：由选品技能在剪辑阶段统一处理为 9:16，投流脚本不再转码
- 页面路径：按“创建页导航规则”自动进入，不让用户或智能体临时找入口
- 上传与挂载：由脚本执行，最终核对主页面 `视频 (n)` 与标题数量

批量执行建议输入为 CSV/JSON，一行一个商品；脚本读取后逐个创建单商品计划并默认自动发布。需要人工逐条确认时，用户必须明确说“只配置到发布前/不发布”，并使用 `--no-publish`。

推荐字段：

```json
{
  "product_id": "1234567890123456789",
  "sale_price": 299,
  "unit_cost": 40,
  "sign_rate": 0.55
}
```

可选字段：

```json
{
  "product_name": "醋酸半身裙女款独特设计感漂亮套装缎面鱼尾裙高级感chic别致穿搭",
  "material_dir": "/path/to/clip_outputs/02_醋酸半身裙女款独特设计感漂亮套装缎面鱼尾裙高级感chic别致穿搭",
  "title": "醋酸缎面鱼尾半身裙 高级感显瘦穿搭",
  "daily_budget": 300
}
```

如果可选字段缺失，优先脚本自动推导；只有推导失败才补问。

## 先做的检查

1. 确认 `9222` 可连接。
2. 先枚举 `http://127.0.0.1:9222/json/list`，确认当前页面 URL。
3. 当前页面应是巨量/千川相关页面，且账号已登录。
4. 如果当前 URL 是 `https://qianchuan.jinritemai.com/home...`，这是千川首页，不是投放创建页；不要在首页盲目找半天，按“创建页导航规则”进入创建页。
5. 如用户提供了流程文档，先读取文档，再执行页面操作。
6. 如商品 ID 已下架或不可投，向用户说明后改选现有商品继续流程，不要卡死在原商品上。
7. 如用户未明确给 ROI，先按“ROI 计算规则”计算或补问关键参数，不要沿用页面默认 ROI。

## 创建页导航规则

目标创建页 URL 包含：

`qianchuan.jinritemai.com/uni-creation/product`

执行投流前必须先让 `9222` 中的一个 tab 到达该路径。推荐顺序：

1. 如果已有 tab URL 包含 `/uni-creation/product`，直接复用该 tab。
2. 如果已有千川首页 URL 含 `aavid=...`，必须带上账号参数直达：`https://qianchuan.jinritemai.com/uni-creation/product?aavid=<aavid>`。
3. 不要裸跳 `https://qianchuan.jinritemai.com/uni-creation/product`；实测会被拉回 `/login` 或账号选择页。
4. 如果进入 `/login` 的“选择账户”页，按目标账号名或 `aavid` 选择账户，再回首页提取 `aavid`。
5. 如果必须从首页点入口，不要点数据概览里的 `新建计划`；实测该按钮会创建 `直播全域投放` tab。优先使用带 `aavid` 的商品创建页 URL。
6. 如果直达失败，再在首页只找这些入口词：`商品全域投放`、`商品投放`、`投放商品`、`控成本投放`、`推商品`。
7. 如果 2-3 分钟内仍无法进入创建页，不要继续消耗 token 猜界面；直接告诉用户：请先在 9222 浏览器中手动打开商品全域投放创建页，然后继续自动化。

创建页判定：

- URL 包含 `/uni-creation/product`。
- 页面正文应出现 `商品`、`预算`、`ROI`、`添加视频`、`发布计划` 中的多个关键词。
- 只有 `/home`、`数据概览`、`账户余额`、`营销活动` 等首页内容时，不算创建页。
- URL 包含 `/uni-creation/live` 是直播全域投放，不是商品全域投放；不要继续在该 tab 上配置商品计划。

## ROI 计算规则

ROI 口径来自 `references/roi-calculation.md`，源头是内部出价表。执行投放参数前必须处理 ROI：

### 动态参数

触发投流 skill 时，优先从用户当前消息、项目记录或商品资料中提取 ROI 动态参数。最低必需参数是：

- `sale_price`：售价/客单价
- `unit_cost`：成本价
- `sign_rate`：签收率

本 skill 的固定测算口径：

- `ship_rate`（发货率）：固定 `0.9`
- `profit_rate`（利润率）：固定 `0.01`

除非用户明确要求改口径，否则不补问发货率/利润率，也不沿用其他默认值。

用户如果像 `售价299/成本价40/签收率50` 这样给出，应解析为：

- `sale_price = 299`
- `unit_cost = 40`
- `sign_rate = 0.5`

不要把百分数 `50` 当成 `50.0`，必须转成 `0.5`。发货率、利润率也同理，例如 `发货率90` 解析为 `ship_rate = 0.9`，`利润率1` 解析为 `profit_rate = 0.01`。

默认值只允许在用户未提供对应参数时使用：

- `ship_rate`：默认 `0.9`
- `profit_rate`：默认 `0.01`
- `commission_rate`：默认 `0.05`
- `shipping_fee`：默认 `0`

如果用户提供了 ROI 表截图或 Excel 结果，以截图/Excel 中的参数优先复算。看到类似 `签收率 55.00% / 发货率 90.00% / 利润率 1.00% / 售价 299 / 成本 40` 时，等价于固定口径：

```bash
node ~/.agents/skills/qianchuan-launch-sop/scripts/calc_roi.js \
  --sale-price 299 \
  --unit-cost 40 \
  --sign-rate 0.55 \
  --ship-rate 0.9 \
  --profit-rate 0.01
```

该口径输出 `target_roi = 2.5379`，页面填写 `2.54`。不要再用旧口径算成 `3.25`。

如果缺少最低必需参数，先补问；除非用户明确给了 ROI，否则不要继续填写页面 ROI。

1. 用户明确给 ROI：直接使用用户值，页面保留 2 位小数。
2. 用户没给 ROI，但给了售价、成本、签收率：按 `references/roi-calculation.md` 计算，发货率固定 90%，利润率固定 1%。
3. 用户只给部分参数：优先补齐 `sale_price`、`unit_cost`、`sign_rate`；不要擅自用页面默认 ROI。
4. 如果算出的 `allowable_ad_cost <= 0`，当前利润模型不可投，停止配置并向用户说明。
5. 多 SKU 时必须使用 SKU 占比加权，不能只拿最低价或最高价。

推荐调用：

`scripts/calc_roi.js`

示例：

```bash
node ~/.agents/skills/qianchuan-launch-sop/scripts/calc_roi.js \
  --sale-price 32 \
  --unit-cost 16 \
  --sign-rate 0.8 \
  --profit-rate 0.01
```

用户给出 `售价299/成本价40/签收率50` 时：

```bash
node ~/.agents/skills/qianchuan-launch-sop/scripts/calc_roi.js \
  --sale-price 299 \
  --unit-cost 40 \
  --sign-rate 0.5
```

脚本默认会使用 `ship_rate = 0.9`、`profit_rate = 0.01`。

如果签收率是 `55%`，页面值是 `2.54`，不是 `3.25`。

输出里的 `page_fill_roi` 才是页面填写值。

## 标准执行流程

1. 按“创建页导航规则”进入目标账号与创建页。
2. 确保当前页是单商品新建页，再只添加当前商品。
3. 按“ROI 计算规则”确认 ROI，再设置投放方式、预算、ROI 等参数。
4. 勾选 `自选投放素材`。
5. 添加本地视频素材。
6. 补标题，确认素材数量；发布前必须确认所有标题输入框均为 5-55 字，且无空标题行/重复标题行。
7. 默认点击 `发布计划` 并处理发布确认弹窗；如果用户明确要求不发布，使用 `--no-publish` 停在发布前。

## 今日已验证的创建页修复

以下几项已经在真实 9222 创建页验证过，后续智能体不要再从头摸索：

1. 商品选择弹窗确认后，主页面不一定稳定显示商品 ID。
   - 不要把“主页面必须出现目标商品 ID”作为唯一成功条件。
   - 创建页成功判定应接受：
     - `已添加：1/30`
     - `继续添加商品`
     - 商品卡已回填
   - 商品选择弹窗关闭后，如果主页面已经是单商品状态，不要再回头找商品弹窗，更不要立刻刷新重置。

2. 商品弹窗里的 `确定` 必须按弹窗作用域精确点击。
   - 不要全页面反向找最后一个 `确定`。
   - 必须先确认 `已选 1/30` 稳定，再点击当前商品弹窗底部的 `确定/完成`。
   - 点击后优先等待“弹窗关闭 + 主页面单商品回填”。

3. ROI 计算必须把百分数入参转成小数。
   - `签收率50` = `0.5`
   - `签收率55` = `0.55`
   - `发货率90` = `0.9`
   - `利润率1` = `0.01`
   - `售价299/成本40/签收50` 当前页面应填 `2.80`
   - `售价299/成本40/签收55` 当前页面应填 `2.54`

4. `自选投放素材` 的开关必须只点它自己的 checkbox。
   - 不要点击整张卡片，不要模糊命中 `智能优选素材` 区域。
   - 成功判定必须同时满足：
     - `自选投放素材` checkbox 已勾选
     - `添加视频` 按钮可见

5. `选择要添加素材的商品` 只能在下拉弹层里选，不要在整页搜商品 ID。
   - 之前的错误是：整页搜到包含商品 ID 的大容器后，`querySelector('input[type=checkbox]')` 命中了别的 checkbox，把 `自选投放素材` 又关掉了。
   - 正确做法：
     - 先点 `选择商品：`
     - 只在下拉列表/option 区域里找目标商品
     - 只点击该 option 自己的 checkbox
   - 如果主页面已经显示 `选择商品：<商品名>` 且不是 `请选择`，视为创意商品已选中。

6. 标题区不是一开始就展开。
   - 先点 `添加标题`
   - 再找 placeholder 为 `请输入标题或使用系统推荐标题` 的输入框
   - 最终必须看到标题输入框里已有值，不能只看到 `添加标题` 按钮
   - 标题必须为 5-55 字；看到 `标题长度必须为 5-55` 或 `请输入5-55个字的创意标题`，必须先修复标题再发布。
   - 千川会自动保留一个空的“新增标题”输入行；不要反复填这个空行，否则页面会继续追加新空行。
   - 正确策略：最多保留 3 个有效且不重复的标题，多余标题行直接点击右侧删除图标。

7. 选品阶段必须已输出 9:16 合规素材，投流只上传不转码。
   - 投流脚本不负责重新剪辑。
   - 遇到 `素材尺寸（宽度）不符合规范`，应回到选品/剪辑阶段重出素材。

8. 不要为了“干净验证”重置已上传成功的创建页。
   - `_qc_reset_ts` 会把当前创建页回到空计划状态，已回填的视频会丢失。
   - 如果视频已经回填到主页面，继续补标题、ROI、创意商品等后半段；不要重置。
   - 如果重跑同一商品且主页面 `视频 (n)` 已经大于等于本地待上传视频数，创建脚本会跳过重复上传，并在输出里标记 `action: "skip_upload_existing_main_videos"`。
   - 如果视频已上传到弹窗素材库但还没回填主页面，上传脚本允许复用当前弹窗可见的同名视频并直接勾选确认；不要重复传同一批文件。
   - 批量上传时，如果某个视频进度长时间停在非 100% 状态，上传脚本必须删除该视频行并只重传该文件，不要原地等待到总超时。

9. 发布确认弹窗已验证。
   - 点击 `发布计划` 后可能出现“为保证全域投放的唯一性”的二次确认弹窗。
   - 脚本必须先勾选 `不再提示`，再点击弹窗内的 `确认发布`。
   - 如果已经勾过 `不再提示`，后续可能不再弹窗；不能因此把“没弹窗”当成失败。
   - 发布等待不能串行死等确认弹窗；应同时检测“确认弹窗出现 / 页面跳转到投放管理 / 发布失败提示”。
   - 没有二次确认弹窗时，脚本应立即进入发布结果检测，不能固定白等 15 秒。
   - 发布阶段可能先出现短暂 `发布失败/失败原因` 提示，然后实际发布成功；不要一看到错误 toast 就立刻判失败，至少等待约 6 秒确认是否跳转到投放管理页。
   - 发布成功判定以页面跳转到投放管理页、URL 包含 `/uni-prom` 或不再出现 `发布计划` 为准。

## 本地视频上传规则

### 规则

- 优先使用英文、数字、下划线文件名。
- 如果桌面文件名包含中文，且站点出现兼容问题，先让用户重命名，再继续。
- 多视频时逐条校验：平台可能接受其中一条、拒绝另一条。

### 推荐方式

优先调用：

`scripts/upload_local_videos.js`

示例：

```bash
node ~/.agents/skills/qianchuan-launch-sop/scripts/upload_local_videos.js \
  ~/Desktop/20260413-224402.mp4 \
  ~/Desktop/edit.mp4
```

该脚本会：

- 连接 `9222`
- 打开 `添加视频 -> 上传视频 -> 本地上传`
- 通过 CDP 拦截 file chooser 注入本地文件
- 等待上传结果
- 勾选成功上传的视频
- 点击 `确定`
- 返回最终的 `视频 (n)` 数量

## 失败分支

### 商品下架

- 不要反复搜索失效商品。
- 直接告知用户原商品不可用。
- 改选当前店铺现有商品，继续走流程。

### 上传控件异常

先读：

`references/site-patterns/qianchuan-jinritemai.md`

关键判断：

- 如果页面没有标准 `input[type=file]`，不要继续用网页原生 `upload` 命令硬塞。
- 优先走 CDP 拦截 file chooser。
- 如果上传完成但主页面 `视频 (n)` 没增加，说明素材中心有了，但计划里没挂上；继续在当前弹层里勾选成功视频并点 `确定`。

### 视频不合规

常见失败：

- 分辨率/宽度不符合规范
- 上传后平台显示尺寸错误

处理方式：

- 直接回到选品技能重剪并输出 9:16 素材
- 明确指出被拒绝的文件名和原因
- 不要在投流脚本里临时转码兜底
